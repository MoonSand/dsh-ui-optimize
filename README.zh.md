# dsh-ui-optimize

[English](README.md) | 中文

给 DeepSeek Harness 界面换主题、把「刷新界面 / 重启应用」收进同一个插件，并把侧栏的面板列表收成一个入口——三个功能各自独立开关。

- **主题画廊**：8 套极简主题，浅色与深色各定义一组配色，点一张卡片整套配色生效
- **桌面操作**：侧栏底部的刷新与重启按钮，可分别关掉
- **侧栏收纳**：面板行收成一个「面板」入口，点开是两列启动面板

配色只通过 `ctx.theme.overrideTokens` 以**单层**覆盖主题变量，不注入任何结构性 CSS、不读写其他插件的 DOM，所以宿主改版最多让颜色不生效，不会把界面layout弄坏。

## 安装

```
dsh plugin 或 GUI 插件管理：安装 @moonsand/dsh-ui-optimize
```

要求 `engines.dsh >= 0.2.1-rc.3`。

## 使用

打开 **设置 → 界面优化**。

### 主题

| 主题 | 风格 |
|---|---|
| 青瓷 | 冷调青绿，克制安静 |
| 亚麻 | 暖调棕褐，像未漂白的布 |
| 奶油 | 淡黄暖白，柔和护眼 |
| 石墨 | 近单色中性，冷静克制 |
| 靛蓝 | 近白画布配冷靛强调 |
| 雾蓝 | 蓝灰中性，现代后台的默认脸 |
| 苔绿 | 低饱和绿，比青瓷更松弛 |
| 玫瑰 | 灰调玫瑰，暖而不吵 |

选「默认」恢复原生外观。每套主题为浅色与深色各定义一组配色，切换「外观」里的浅色/深色时自动跟随，不需要为两种模式各选一次。

### 桌面操作

两个开关分别控制侧栏底部的「刷新界面」和「重启应用」按钮：

- **刷新界面**：只重新加载页面与客户端插件，Host 与正在跑的任务不受影响
- **重启应用**：重启整个应用（含 Host），会中断当前对话；**仅桌面端可用**，网页端会降级为刷新页面

### 侧栏

一个开关把左侧竖栏里的面板行收成一个「面板」入口。点开是两列启动面板：图标、标题与数量、面板多于 7 个时出现搜索框，并支持键盘操作（↑ ↓ 移动、回车打开、Esc 关闭）。之后才注册的面板——包括其他插件加进来的——在下次打开时自动出现，不会漏。

入口走宿主自己的面板选中接口，不伪造点击。挂载后与每次缩放时都有一个看门狗在量尺寸：量不到就把开关自动关掉、还原原生侧栏，而不是留一根空栏。

「更多」保持独立一行。把它也收进去试过并放弃了：宿主的溢出菜单只认真实点击，插件造不出来；而伪造的指针事件又会被宿主的「点外部即关闭」吃掉，刚打开的弹层立刻被关掉。

## 与 dsh-desktop-restart 的关系

本插件的桌面操作移植自 [`@moonsand/dsh-desktop-restart`](https://github.com/MoonSand/dsh-desktop-restart)，并已改用独立的路由前缀 `/ui-optimize/desktop`。

两个插件**可以同时安装而不会崩溃**，但会出现两套刷新/重启按钮。检测到旧插件仍在运行时，设置页顶部会给出提示，建议卸载它。

## 已知限制

- 主题选择保存在浏览器 `localStorage`，换机器或清站点数据会丢失
- 重启只适用于桌面端；网页端只能刷新
- 重启日志仍写在 `%TEMP%\dsh-desktop-restart.log`（沿用移植来源的路径）
- 重启动作为进程级操作，无法在自动化测试中验证，只能人工点一次确认
- 「更多」没有收进弹层，仍在原生竖栏里
- 弹层沿用宿主自己的面板顺序，不排序、不置顶、不重排
- 侧栏收纳与 `dsh-sidebar-shelf` 改的是同一根竖栏，两个只能开一个

## 开发

```
node scripts/smoke.mjs
```

冒烟只验证装配契约：三个运行时文件可解析、主题表结构完整（8 套 × 10 个变量 × 浅/深两组）、包身份与 `engines.dsh` 完好。**它不验证配色观感，也不验证重启是否真的重启。**
